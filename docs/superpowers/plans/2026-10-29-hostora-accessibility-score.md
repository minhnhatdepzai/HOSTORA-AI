# HOSTORA Accessibility Score Improvement Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the verified web/admin axe failures and prevent Android launch overlays from exposing hidden controls, while making recommendation costs easier to reach without hiding commercial facts.

**Architecture:** Keep this a targeted remediation: web/admin changes stay in existing components and CSS; Android overlay state is centralized in a small pure accessibility helper used by the root layout; recommendation disclosure copy is generated by a pure helper and rendered as a native expandable control. Deterministic ranking, pricing and local-first AI boundaries do not change.

**Tech Stack:** Next.js App Router, React 19, CSS/Tailwind utilities, axe-core/Playwright, Expo Router, React Native, Vitest, Mobile MCP/ADB.

**Spec:** `docs/submission/FULL_PRODUCT_REVIEW_AND_95_PLAN_2026-10-29.md`

## Global Constraints

- Preserve the user's uncommitted `output/hostora-redmi-connected.png`.
- Keep Ollama loopback-only and do not change deterministic pricing/ranking.
- Prefer native semantics and minimal targeted accessibility changes.
- All customer-facing text remains Vietnamese and all commercial caveats remain truthful.
- Android validation must update with `adb install -r`; never uninstall or clear app data.
- A passing browser mobile viewport does not replace native Redmi evidence.

## Review Focus

- The first Android launch may show BrandFilm and then Onboarding; the routed screen must stay hidden from accessibility through both overlays.
- Reduced-motion users skip BrandFilm but may still see Onboarding; the routed screen must remain hidden until Onboarding closes.
- A user who expands cost details must still see promo term, upfront amount, renewal and unverified values without invented data.
- Both desktop and 390 px audit viewports must have zero axe violations on all six audited routes.
- Revenue charts need a valid accessible semantic without making decorative chart internals noisy.
